Phase 0 answered whether a band this short can read as a place at all — First Light's dawn horizon did, once the source grid doubled so a circle and a canopy had room to round out. Phase 1's question is different: can one format carry different places? The same six-token palette and the same silhouette grammar, drawing a bakery, a harbor, and a mountain alongside First Light. What this spike deliberately skips. No agent, no store, no validator, no register map, no tests — the grid below is inline data and the painter is ~40 lines. If a band this short does not read as a place, the rest of the register-scene plan is discarded having cost this one file.

What this pass actually found. First Light, the harbor, and the mountain all read clearly as their register once two real bugs were fixed (an invisible sail, a mountain peak tall enough to clip its own summit off-canvas). The bakery does not — two different structural attempts at a shopfront both read as abstract blocks rather than a building, at both grid sizes. That is the horizon-band grammar's actual limit surfacing, not a drawing-skill problem to iterate away quietly: a landscape has a horizon to organise around, and a street-level scene does not. Worth carrying into Phase 3 rather than reworking here. The same session also found one bug three times in three shapes: the palest token in the palette is invisible against the sky band it shares that exact color with, so a snow cap, then a chimney's smoke, both vanished until given a token that contrasts with its LOCAL background, not merely one that is in the six-token set.
